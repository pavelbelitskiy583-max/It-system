# ECHOIT — IT-мастерская вашей компании

Единая система управления IT-инфраструктурой: склад, оборудование по филиалам/этажам/кабинетам,
картриджи с историей заправок, задачи, внутренний мессенджер и защищённое хранилище доступов.

Стек: **React + Vite**, без бэкенда — все данные хранятся в `localStorage` браузера
(с возможностью экспорта/импорта JSON-резервной копии). Пароли пользователей хешируются
(SHA-256 + соль), записи в «Доступах» шифруются **AES-GCM** (ключ выводится из кода доступа
сейфа через PBKDF2, Web Crypto API).

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес, который выведет Vite (обычно `http://localhost:5173`).

Для сборки production-версии:

```bash
npm run build
npm run preview
```

## Как пользоваться

1. На лендинге нажмите **«Создать организацию»** — это регистрация администратора.
2. Администратор в разделе **«Настройки → Филиалы»** добавляет филиалы, этажи и кабинеты.
3. В **«Настройки → Сотрудники»** администратор создаёт учётки: указывает имя и логин,
   система сама генерирует пароль (показывается один раз — его нужно передать сотруднику лично),
   и отмечает чекбоксами, какие модули сотруднику доступны.
4. При первом входе сотрудника система попросит задать собственный пароль.
5. Раздел **«Доступы»** при первом открытии просит администратора задать код доступа к сейфу.
   Далее к каждой записи (пароль/VPN/API-ключ/инструкция) можно отдельно указать, каким
   сотрудникам она видна — остальным запись не отображается вовсе.

## Важно понимать про хранение данных

Это **фронтенд-прототип без сервера**: все данные организации живут в `localStorage` конкретного
браузера на конкретном устройстве. Это значит:

- Работает офлайн и без деплоя бэкенда — отлично для демонстрации и обкатки процессов.
- Данные не синхронизируются между разными компьютерами/сотрудниками автоматически.
- Есть кнопка экспорта/импорта JSON («Настройки → Данные») для переноса данных.

Для реальной многопользовательской эксплуатации (несколько сотрудников одновременно, с разных
устройств) потребуется вынести хранилище на сервер (например, Node/Express + PostgreSQL, или
Supabase/Firebase) и заменить функции в `src/context/DataContext.jsx` и `src/context/AuthContext.jsx`
на HTTP/WebSocket-запросы — структура данных и UI-слой для этого уже готовы и не потребуют
переделки.

## Структура проекта

```
src/
  context/
    AuthContext.jsx   — организации, пользователи, роли, права, сессия
    DataContext.jsx    — филиалы/этажи/кабинеты, склад, картриджи, оборудование, задачи, чат, сейф
  lib/
    crypto.js           — хеширование паролей и AES-GCM для сейфа
    storage.js          — localStorage + экспорт/импорт JSON
    id.js                — генерация id и случайных паролей
  layout/
    Shell.jsx            — сайдбар/топбар приложения
    Guards.jsx           — защита маршрутов (вход обязателен / нужны права модуля / только админ)
  pages/
    Landing.jsx, Auth.jsx, Dashboard.jsx, Warehouse.jsx, Cartridges.jsx,
    Equipment.jsx, Tasks.jsx, Messenger.jsx, Vault.jsx, Settings.jsx
  components/
    Icons.jsx            — монохромные line-art иконки
    PageHeader.jsx
  styles.css              — единая дизайн-система (тёмная, Sora + JetBrains Mono)
```

## Демо-медиа в hero

Видео и постер в hero используют те же CloudFront-ссылки, что были в исходном ТЗ. Замените их
на собственные в `src/pages/Landing.jsx` и `src/pages/Auth.jsx` (константы `VIDEO_URL`, `POSTER_URL`),
когда появится собственный видеоряд.
